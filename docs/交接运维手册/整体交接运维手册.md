# 第一部分：项目概览（给所有人）

## 1.1 这是什么
**AooBee（www.aoobee.com）** 是一个以 **GEO（生成式引擎优化，让 AI 问答引用你）** 和 **SEO（搜索引擎收录）** 为核心目标的内容目录站。内容覆盖 8 大生活/工具分类，形态包括：榜单、对比、编辑评测、指南、问答、用户点评、产品页。

## 1.2 业务目标（为什么这么建）
- **被 AI 引用**：通过结构化数据（FAQPage / Article / Review / Rating / Organization）和 `llms.txt`，让 ChatGPT / Claude / Perplexity / Gemini 在回答相关问题时直接引用本站内容。
- **被搜索引擎收录**：纯静态页面、清晰的 `sitemap.xml`、`robots.txt` 全开 AI 爬虫、正确的 `canonical` 与 OG 图。
- **低成本可维护**：Markdown 即源，git 版本化，非技术编辑也能用 Obsidian 管理。

## 1.3 技术栈
- **框架**：Next.js 16（App Router）+ React 19 + TypeScript
- **渲染**：纯 SSG（静态站点生成），**无 ISR**（内容改动走整站重建部署，约 1–2 分钟）
- **部署**：Vercel（serverless，非静态导出；`next.config` 不含 `output:'export'`）
- **内容源**：`content/` 下的 Markdown + frontmatter（gray-matter 解析）
- **字体**：`assets/fonts/NotoSansSC.ttf`（子集化中文字体，必须进仓库，Vercel=Linux 无系统中文）
- **依赖**：`openai` 真用于 `src/lib/llm/index.ts`（LLM 辅助能力，非冗余）
- **分析**：GA4 + Microsoft Clarity 已接入（`src/components/analytics.tsx`），可看人类流量与页面热力。

## 1.4 部署数据流（内容怎么变成网页）
```

   │  loader.ts 解析 frontmatter + 正文
   ▼

   │  Next.js 构建期
   ▼
```

## 2.2 内容加载管线
- `loader.ts` 用 `DIR_TO_TYPE` 映射文章子目录→类型；`parseReviews` 单独解析 `content/reviews/`。
- **文章页双 h1 修复**：`parseArticle` 会剥离正文首行 `# 标题`（模板已渲染 `<h1>{title}</h1>`，避免重复 h1）。
- `metaDesc` 优先级链：`description` 字段 → `metaDesc` 字段 → 正文派生（确保用 frontmatter 自写描述，而非 FAQ 拼接）。
- `types.ts` 的 `Article` 含可选 `related`、`definition`、`definitionTerm`、`audience` 字段。
- `related.ts` 的 `resolveRelated`：把 `related` 里的路径解析成 `{title, href}`，**解析不到自动过滤，不产生死链**。

## 2.3 自动化生成（勿手改）
- **结构化数据**：`schema.ts` 按页面类型注入 JSON-LD（首页 Organization+WebSite；文章 Article+FAQPage+Breadcrumb；产品 SoftwareApplication+AggregateRating+Offer+FAQPage）。
- **llms.txt / sitemap.xml / robots.txt**：构建期自动生成（sitemap 已含 /categories/ 入口）。
- **OG 图**：`opengraph-image.tsx` 原生约定，运行时 `image/png`，不手生成 `.png`、不写 `public/og/`。

# 第三部分：内容系统约定（核心）

## 3.1 URL ↔ 目录 ↔ frontmatter 映射

| 页面 URL | 文件位置 | frontmatter 必含 `type` |
|---|---|---|
| 榜单 `/best/<slug>` | `content/articles/best/<slug>.md` | `BEST` |
| 对比 `/compare/<slug>` | `content/articles/compare/<slug>.md` | `COMPARISON` |
| 编辑评测 `/review/<slug>` | `content/articles/review/<slug>.md` | `REVIEW` |
| 指南 `/guide/<slug>` | `content/articles/guide/<slug>.md` | `GUIDE` |
| 问答 `/faq/<slug>` | `content/articles/faq/<slug>.md` | `FAQ` |
| 用户点评 `/reviews/<slug>` | `content/reviews/<slug>.md` | **无 type 字段** |
| 产品页 `/<category>/<slug>` | `content/products/<category>/<slug>.md` | **无 type 字段** |
| 分类总览 `/categories/` | `content/categories/<slug>.md` | — |

⚠️ **最易踩坑**：`content/reviews/`（用户点评）与 `content/articles/review/`（编辑评测）是**两套完全不同的内容**，frontmatter 格式不同，绝不可混放。点评必须进 `content/reviews/`。

## 3.2 固定分类（8 个，slug 不可改）
`zhuangxiu`(装修) / `jiadian`(家电) / `yuer`(育儿) / `weixiu`(维修) / `bangong`(办公) / `yanglao`(养老) / `jiaoyu`(教育) / `ai`(AI)
文章与产品的 `category` 字段必须取这 8 个之一。

## 3.3 三类 frontmatter 模板（直接复制）

**文章类**（best/compare/review/guide/faq 通用，仅换 `type`）：
```yaml
---
title: 标题
type: BEST            # BEST|COMPARISON|REVIEW|GUIDE|FAQ
category: ai          # 8 选 1
keywords: [关键词1, 关键词2]
excerpt: 一句话摘要（卡片用）
description: SEO 描述，≤160 字
authorName: AooBee 编辑部
publishedAt: 2026-07-31
faqItems:
  - question: 常见问题？
    answer: 回答。
definition: 什么是 X（可选，填了覆盖分类默认定义块）
definitionTerm: X（可选）
audience: X 适合谁（可选，填了覆盖分类默认受众块）
related:
  - /compare/chatgpt-vs-claude
  - /ai/chatgpt
---
# 正文标题
正文 Markdown……
```

**用户点评类**（`content/reviews/`，字段不同）：
```yaml
---
title: ChatGPT 真实使用点评
product: chatgpt      # 必须 = 对应产品文件 slug
author: AooBee 编辑部
rating: 4.7
pros: [优点1, 优点2]
cons: [缺点1, 缺点2]
summary: 一句话总评
description: SEO 描述
related:
  - /review/chatgpt-review
  - /best/ai-writing-tools-2026
  - /ai/chatgpt
---
正文……
```

**产品类**（`content/products/<category>/`）：
```yaml
---
name: ChatGPT
description: 一句话介绍
category: ai
url: https://chat.openai.com
company: OpenAI
pricing: 免费 / Plus $20

  - name: 多轮对话
    description: 基于上下文的连续对话
pros: [生态成熟, 插件丰富]
cons: [需联网, 免费版有限额]
useCases: [写作辅助, 编程]
faqItems:
  - question: ChatGPT 收费吗？
    answer: 有免费版，Plus $20/月。
alternatives: [claude]   # 可选；不填自动取同分类评分 Top5
---
产品正文（纯文本段落，按空行切分；**不解析 Markdown**）
问答只写进上面的 faqItems，不要写在正文里。
```

> ⚠️ **产品页编写规矩**：产品页正文按空行切成**纯文本段落**渲染，**不解析 Markdown**（不要写 `# 标题`、列表、`**加粗**` 等语法，会被当纯文本显示）。所有问答必须写进 `faqItems` 字段（由 FaqSection 渲染并生成 FAQPage 结构化数据），**不要**写进正文。

**分类类**（`content/categories/<slug>.md`）：
```yaml
---
slug: ai
name: AI 工具
description: 分类一句话介绍
icon: 🤖
order: 8
published: true
---
```

## 3.4 `related` 内链规则（核心机制）
- 元素是**路径字符串**或 `{ href, title }` 对象。
- 仅接受：文章段 `/best/x`、`/compare/x`、`/review/x`、`/guide/x`、`/faq/x`；点评 `/reviews/x`；产品 `/<category>/x`。
- 写错**不会报错但被静默过滤**（页面不显示相关阅读）。
- 产品页「相关阅读」按分类自动聚合，无需手写 `related`。

## 3.5 定义块字段（P1-b，可选）
`definition` / `definitionTerm` / `audience` 三个可选字段。字段缺失时自动回退到**分类真实描述**（8 分类受众映射），故现有文章零改动即获「什么是 X / X 适合谁」块；新文章可填字段精准化。

## 3.6 slug 命名
- slug 用 kebab-case 英文（出现在 URL）；中文写在 `title`。
- 文件名即 slug（不含 `.md`）。
