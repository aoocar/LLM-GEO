# 第一部分：项目概览（给所有人）

## 1.1 这是什么
**AooBee（www.aoobee.com）** 是一个以 **GEO（生成式引擎优化，让 AI 问答引用你）** 和 **SEO（搜索引擎收录）** 为核心目标的内容目录站。内容覆盖 8 大生活/工具分类，形态包括：榜单、对比、编辑评测、指南、问答、用户点评、产品页。

## 1.2 业务目标（为什么这么建）
- **被 AI 引用**：通过结构化数据（FAQPage / Article / Review / Rating / Organization）和 `llms.txt`，让 ChatGPT / Claude / Perplexity / Gemini 在回答相关问题时直接引用本站内容。
- **被搜索引擎收录**：纯静态页面、清晰的 `sitemap.xml`、`robots.txt` 全开 AI 爬虫、正确的 `canonical` 与 OG 图。
- **低成本可维护**：Markdown 即源，git 版本化，非技术编辑也能用 Obsidian 管理。

## 1.3 技术栈
- **框架**：Next.js 16（App Router）+ React 19 + TypeScript
- **渲染**：纯 SSG（静态站点生成），**无 ISR**（内容改动走整站重建部署，约 1–2 分钟）
- **部署**：Vercel（serverless，非静态导出；`next.config` 不含 `output:'export'`）
- **内容源**：`content/` 下的 Markdown + frontmatter（gray-matter 解析）
- **字体**：`assets/fonts/NotoSansSC.ttf`（子集化中文字体，必须进仓库，Vercel=Linux 无系统中文）
- **依赖**：`openai` 真用于 `src/lib/llm/index.ts`（LLM 辅助能力，非冗余）

## 1.4 部署数据流（内容怎么变成网页）
```
content/*.md (Markdown 源)
   │  loader.ts 解析 frontmatter + 正文
   ▼
src/app/(content)/... 页面模板 (best/compare/review/guide/faq/reviews/products)
   │  Next.js 构建期
   ▼
自动产出：
  ├─ 静态 HTML 页面（/best/x、/ai/chatgpt …）
  ├─ /sitemap.xml        （66 条 URL）
  ├─ /llms.txt           （67 条 AI 爬虫地图）
  ├─ /robots.txt         （Allow 全部 AI 爬虫）
  └─ OG 图 (opengraph-image.tsx 运行时 image/png)
   │  push 到 GitHub → Vercel 监听 → 自动部署
   ▼
www.aoobee.com 线上生效
```

# 第二部分：技术架构（给开发者）

## 2.1 关键目录结构
```
src/
  app/
    page.tsx                      # 首页（注入 WebSite + Organization JSON-LD）
    layout.tsx                    # 全局布局
    (content)/
      best/[keyword]/page.tsx     # 榜单
      compare/[slug]/page.tsx     # 对比
      review/[slug]/page.tsx      # 编辑评测
      guide/[slug]/page.tsx       # 指南
      faq/[slug]/page.tsx         # 问答
      reviews/[slug]/page.tsx     # 用户点评
    [category]/[slug]/page.tsx    # 产品页（按分类聚合相关阅读）
  components/
    directory/related-reads.tsx   # 相关阅读组件
    directory/definition-block.tsx # 定义块组件（P1-b）
    seo/json-ld.tsx                # JSON-LD 注入组件
  lib/
    content/types.ts              # Article/Review 接口（已预留 Prisma 字段对齐）
    content/loader.ts             # 解析 Markdown → 结构化对象
    content/related.ts            # resolveRelated 路径→{title,href}
    seo/schema.ts                 # organizationSchema / websiteSchema / 各类 schema
content/
  articles/{best,compare,review,guide,faq}/*.md
  reviews/*.md                    # 用户点评（独立目录！）
  products/<category>/*.md
  categories/*.md
docs/  .workbuddy/memory/  AGENTS.md  next.config.ts  vercel.json
```

## 2.2 内容加载管线
- `loader.ts` 用 `DIR_TO_TYPE` 映射文章子目录→类型；`parseReviews` 单独解析 `content/reviews/`。
- `types.ts` 的 `Article` 含可选 `related`、`definition`、`definitionTerm`、`audience` 字段。
- `related.ts` 的 `resolveRelated`：把 `related` 里的路径解析成 `{title, href}`，**解析不到自动过滤，不产生死链**。

## 2.3 自动化生成（勿手改）
- **结构化数据**：`schema.ts` 按页面类型注入 JSON-LD（首页 Organization+WebSite；文章 Article+FAQPage+Breadcrumb；产品 SoftwareApplication+AggregateRating+Offer+FAQPage）。
- **llms.txt / sitemap.xml / robots.txt**：构建期自动生成。
- **OG 图**：`opengraph-image.tsx` 原生约定，运行时 `image/png`，不手生成 `.png`、不写 `public/og/`。

## 2.4 部署与配置
- `next.config.ts`：无 `output:'export'`，纯 serverless SSG；`trailingSlash: true`（注意：`/best/x` 会被 308 重定向到 `/best/x/`，curl 抓页需加 `-L`）。
- `vercel.json`：无特殊重定向冲突。
- 字体文件 `NotoSansSC.ttf` 必须进仓库（Linux 无系统中文）。

## 2.5 已知技术状态
- **无 ISR**：纯 SSG，内容改动=整站重建。当前 ~66 节点可接受；到数千节点需评估构建时长。
- **`out/` 目录**：早期静态导出实验残留，已被 `.gitignore` 忽略、零 git 跟踪，**无害**，本地可手动删。
- **`.next_stale/`**：构建时因沙箱删除保护移走的旧构建目录，非仓库文件，本地可删（见 9.6）。

## 3.4 `related` 内链规则（核心机制）
- 元素是**路径字符串**或 `{ href, title }` 对象。
- 仅接受：文章段 `/best/x`、`/compare/x`、`/review/x`、`/guide/x`、`/faq/x`；点评 `/reviews/x`；产品 `/<category>/x`。
- 写错**不会报错但被静默过滤**（页面不显示相关阅读）。
- 产品页「相关阅读」按分类自动聚合，无需手写 `related`。

## 3.5 定义块字段（P1-b，可选）
`definition` / `definitionTerm` / `audience` 三个可选字段。字段缺失时自动回退到**分类真实描述**（8 分类受众映射），故现有文章零改动即获「什么是 X / X 适合谁」块；新文章可填字段精准化。

## 3.6 slug 命名
- slug 用 kebab-case 英文（出现在 URL）；中文写在 `title`。
- 文件名即 slug（不含 `.md`）。

# 第四部分：日常运营操作（人工 + AI 共通）

## 4.1 新增内容
1. 把 `.md` 放到 3.1 对应目录（slug = kebab-case 英文）。
2. 本地预览：`npm run dev` → 打开 `http://localhost:3000/<类型>/<slug>`，检查底部「相关阅读」。
3. 提交：`git add content/...` + `git commit -m "新增/修改 xx"`。
4. **push 由用户手动跑**（见 4.3）。
5. 线上验证：URL 是否 200、OG 图、sitemap 是否收录。

## 4.2 修改 / 下架
- 修改：直接编辑对应 `.md`，重新预览+提交+push。
- 下架：删除文件或设 `published: false`（视模板支持），提交后部署即生效。

## 4.3 Git 工作流（铁律）
- **AI 只 `commit`，绝不 `push`**。远程是 HTTPS + Git Credential Manager，弹窗需 `/dev/tty`，沙箱无终端，push 必失败。分工固定：AI 做到 `git add`+`git commit`，**push 由用户在 PowerShell 手动跑**。
- **PowerShell 不支持 `&&`**：给用户的命令用 `;` 或分两行写。
- 推送命令（用户侧）：`cd D:\project\www.aoobee.com` 然后 `git push origin main`。

## 4.4 部署触发
push 到 GitHub `main` → Vercel 自动重建部署（约 1–2 分钟）→ 线上生效。docs/、AGENTS.md 等非 `src/app/` 文件不会变成网页，但会进仓库并触发一次部署（无害，仅费构建额度）。

# 第九部分：技术开发与升级指南

## 9.1 加新字段（标准三步）
1. `src/lib/content/types.ts` 接口加字段（注意顶部已预留 Prisma 字段对齐）。
2. `src/lib/content/loader.ts` 解析该字段。
3. 在对应页面模板渲染（必要时新建组件，如 `definition-block.tsx`）。
> 字段缺失务必做 fallback，保证旧内容零改动不报错。

## 9.2 加新页面类型
- 在 `src/app/(content)/<新类型>/[slug]/page.tsx` 建模板。
- `loader.ts` 的 `DIR_TO_TYPE` 增加映射。
- `types.ts` 增加对应 `type` 枚举值。

## 9.3 内容校验 CI（建议 P2）
- pre-commit / CI 脚本校验：必填字段存在、`related` 路径存在、slug 唯一、category ∈ 8 分类。
- 可以用 Node 脚本读 `content/` 遍历 frontmatter 实现。

## 9.4 扩量四阶段
| 阶段 | 节点量 | 形态 | 动作 |
|---|---|---|---|
| A 当前 | 0–~300 | Markdown+Obsidian+git | 加 `content/_templates/` |
| B 增长 | ~300–1000 | +校验 CI | 按分类拆 git 子仓库 |
| C 多编辑 | ~1000–3000 | +轻量 CMS | Decap/Strapi 输出 markdown，保留 markdown 为源 |
| D 规模化 | 3000+ / 关系查询 | 迁 DB | Prisma+Postgres，`llms.txt`/`sitemap` 改从库生成 |

**原则**：尽量长久保留"Markdown 即源"。只有当"多人并发编辑"或"复杂关系查询"才上数据库。

## 9.5 迁库预留
`types.ts` 顶部已写明"对齐原 Prisma 模型字段，便于最小改动迁移"——架构已预留，无需推倒重来。

## 9.6 本地构建坑（务必知道）
- 构建清理 `.next` 会被沙箱"安全删除"机制拦截，导致 `rm`/`mv` 跨盘失败。**解决**：同盘 `mv .next .next_stale` 后重跑 `npm run build`。
- `.next_stale/`、`out/` 均为残留，非仓库文件，本地可手动删（不影响 git）。
