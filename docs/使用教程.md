# AooBee 使用教程（内容录入与站点维护）

> 本文档适用于 **md 化重构之后**的内容工作流。站点内容全部来自 `content/` 下的 Markdown 文件（建议用 Obsidian 管理），不再使用数据库。
> 旧文档 `docs/手动修改内容教程.md` 描述的是「数据库 + 种子脚本」旧模型，已废弃，请以本文为准。

---

## 0. 这是什么

- **技术形态**：Next.js 静态导出站点（`output: "export"`），构建产物是纯静态文件 `out/`。
- **定位**：面向搜索引擎与 AI 爬虫的 GEO/SEO 内容目录（不是给人用的后台，没有用户交互）。
- **内容源**：`content/` 下的 Markdown 文件，frontmatter 是结构化字段，正文是展示内容。
- **部署**：把 `out/` 丢到任意静态服务器（nginx / Cloudflare Pages / 对象存储）即可。

---

## 1. 内容目录结构

```
content/
├── categories/            # 分类（如 ai.md）
│   └── ai.md
├── products/              # 产品，按分类再分子目录
│   └── ai/
│       └── chatgpt.md
├── articles/              # 文章，按类型分子目录
│   ├── guide/             # 指南  (type: GUIDE)
│   ├── best/              # 推荐  (type: BEST)
│   ├── compare/           # 对比  (type: COMPARISON)
│   ├── faq/               # 问答  (type: FAQ)
│   └── review/            # 评测  (type: REVIEW)
└── reviews/              # 点评（内容类型，挂在某产品下）
    └── chatgpt-honest-review.md
```

> 注意：产品文件必须放在 `content/products/<分类slug>/` 子目录里（子目录名 = 分类 slug）。文章同理放在 `content/articles/<类型>/` 下。

## 2. 各类内容的 frontmatter 字段

### 2.1 分类 `content/categories/<slug>.md`

```yaml
---
name: 人工智能          # 显示名
slug: ai               # URL 片段，必填且唯一
description: AI 工具、模型与平台的综合目录。
icon: 🤖               # 可选，emoji 图标
order: 1               # 排序，越小越靠前
published: true       # false 则不展示
---
正文（分类页顶部介绍，可留空）
```

### 2.2 产品 `content/products/<分类>/<slug>.md`

```yaml
---
name: ChatGPT
description: ChatGPT 是 OpenAI 推出的通用对话 AI……   # 必填！用于 meta description 与 JSON-LD
category: ai            # 对应分类 slug
url: https://chat.openai.com
company: OpenAI
pricing: 免费 / Plus $20
rating: 4.8
tags: [AI, 聊天机器人, 大模型]
features:               # 对象数组，每项 name + 可选 description
  - name: 多轮对话
    description: 基于上下文的连续对话能力
pros: [生态成熟, 插件丰富, 响应快]
cons: [需联网, 免费版有限额]
useCases: [写作辅助, 编程, 知识问答]
faqItems:               # 可选，不写则按上面字段自动生成
  - question: ChatGPT 收费吗？
    answer: 有免费版，Plus 订阅 $20/月。
published: true
---
# ChatGPT

正文详细介绍（Markdown 格式）。无正文时 description 仍会兜底，但建议补足。
```

> **关键点**：产品若没写 `description` 且无正文，产品页 meta description 会缺失（对 SEO 不利）。要么写 `description`，要么在正文里写介绍。

### 2.3 文章 `content/articles/<类型>/<slug>.md`

`guide / best / compare / faq / review` 五个目录共用同一套字段，区别在 `type`：

```yaml
---
title: 如何选择 AI 写作工具
type: GUIDE             # GUIDE / BEST / COMPARISON / FAQ / REVIEW
category: ai            # 可选，关联分类
keywords: [AI写作, 工具选型]
excerpt: 150 字以内摘要（列表卡与 meta 摘要）
authorName: AooBee 编辑部
metaTitle: SEO 标题（60 字内，可选）
metaDesc: SEO 描述（160 字内，可选）
publishedAt: 2026-01-15
updatedAt: 2026-01-15
readTime: 8             # 预估阅读分钟
published: true
---
# 标题

正文（Markdown）。faq 类型建议用 `## 问题` + 段落作答。
```

> `review` 类型（评测文章）与 `reviews/` 目录（用户点评内容）是两回事：前者是文章，后者是挂在产品下的点评内容类型。

### 2.4 点评 `content/reviews/<slug>.md`

```yaml
---
title: ChatGPT 真实使用点评
product: chatgpt        # 对应产品 slug
author: AooBee 编辑部
rating: 4.7
pros: [上下文强, 多模态]
cons: [偶发幻觉, 免费版限额]
summary: 一句话总评（用于 meta description）
description: 更完整的 SEO 摘要（可选）
published: true
---
正文点评内容（Markdown）。
```

## 3. 新增一条内容（最常用流程）

### 方式 A：用脚手架生成（推荐，避免写错字段）

```bash
# 生成产品脚手架（默认分类 ai）
npm run gen:tpl product claude --name "Claude"

# 生成文章 / 分类 / 点评
npm run gen:tpl guide how-to-use-claude --name "如何使用 Claude"
npm run gen:tpl category design --name "设计创意"
npm run gen:tpl reviews claude-review --name "Claude 真实点评"
```

脚本会在对应目录生成带完整字段注释的 `<slug>.md` 骨架（已存在则跳过）。随后用编辑器/Obisidian 填内容即可。

### 方式 B：直接手写 Markdown

按第 2 节的字段模板新建文件保存即可。

### 保存后的必做一步：重新构建

内容改动**不会热更新**（静态站），必须重新构建才会进 `out/`：

```bash
npm run build
```

## 4. 本地构建与预览

```bash
# 1) 构建（生成 out/）
npm run build

# 2) 本地预览 out/（静态伺服）
cd out && python3 -m http.server 4173 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:4173
```

> **Windows 注意**：构建前务必先停掉预览服务（`python http.server` 会锁住 `out/` 目录，导致 `next build` 收尾清理报 `EBUSY`）。停服务：用任务管理器/ `Stop-Process` 结束占用 4173 端口的进程。

> 站点已开启 `trailingSlash: true`，子页导出为 `out/ai/index.html` 形式，干净 URL `/ai`、`/ai/chatgpt` 在静态托管下可直接访问。

## 5. AI 辅助生成（本地 CLI，可选）

适合批量起量。脚本调用 LLM 直接产出 Markdown 内容文件。

```bash
# 单个产品（需要联网 + API Key）
npm run gen product claude --name "Claude" --company "Anthropic" --url "https://claude.ai"

# 单篇文章
npm run gen guide how-to-use-claude --topic "如何使用 Claude" --category ai
npm run gen compare "Claude vs GPT" --category ai
npm run gen faq "claude 是什么" --category ai

# 用户点评内容
npm run gen reviews claude-review --product claude

# 批量（读 JSON 规格）
npm run gen:batch -- --spec scripts/generate-batch.json --concurrency 3
```

**前置条件**（在 `.env` 配置其一）：
- OpenAI：`LLM_PROVIDER=openai` + `OPENAI_API_KEY=...`
- 兼容端点：`LLM_PROVIDER=openai` + `LLM_BASE_URL=...` + `OPENAI_API_KEY=...`
- 其它：`LLM_PROVIDER` 对应的 `apiKeyEnv`（见 `src/lib/llm/index.ts`）

> AI 生成的是草稿，生成后建议人工/Obisidian 复核并补 `description`、`metaDesc` 等 SEO 字段。脚本对已存在的文件会跳过（不覆盖）。

## 6. 自动生成的站点产物

| 文件 | 作用 | 生成时机 |
|---|---|---|
| `out/sitemap.xml` | 搜索引擎收录地图（含全部分类/产品/文章/点评 URL） | `npm run build` |
| `out/robots.txt` | 爬虫规则，显式放行 7 类 AI 爬虫 | `npm run build` |
| `out/llms.txt` | 给 AI 爬虫看的内容地图（Markdown 维护说明） | `npm run build`（由 `scripts/gen-llms.ts`） |

改了内容后直接 `npm run build`，这三个文件会自动更新，无需手动改。

## 7. 部署（方案 2：自托管 + Cloudflare）

1. 本地 `npm run build` 得到 `out/`。
2. 把 `out/` 整个目录传到自有服务器。
3. nginx 伺服静态文件（关键配置）：

```nginx
server {
  listen 80;
  server_name www.aoobee.com;
  root /var/www/aoobee/out;
  index index.html;

  # 干净 URL + 目录补斜杠 + 兜底 404
  try_files $uri $uri/ =404;

  # 静态资源长缓存
  location /_next/static/ { expires 1y; add_header Cache-Control "public, immutable"; }
  location ~* \.(svg|png|jpg|woff2|css|js)$ { expires 30d; }
}
```

4. Cloudflare 前置：DNS 指向服务器，开启 CDN、HTTPS（自动证书）、WAF/速率限制抗 DDoS。

## 8. 常见问题

- **子页打不开 / 列目录？** 已开启 `trailingSlash: true`，nginx 用 `try_files $uri $uri/ =404;` 即可。
- **改了 content 没生效？** 静态站不会热更新，必须 `npm run build` 重构建。
- **产品页没有 meta description？** 在 frontmatter 写 `description`，或在正文补足介绍文字（loader 会自动派生兜底）。
- **标题出现两个 `| AooBee`？** 不应出现；若出现说明某页同时用了 layout 模板与 generateMeta 拼接，检查该页 metadata。
- **JSON-LD 里 logo 404？** 站点 logo 为 `public/logo.svg`，已被文章页 JSON-LD 引用，不要改回 `logo.png`。
- **想加新分类？** 在 `content/categories/` 新建 `<slug>.md`，并把该分类下的产品放进 `content/products/<slug>/`。页脚与导航会自动出现。

---

## 9. 推荐工作顺序

1. 用 `npm run gen:tpl` 或手写，新增/修改 `content/` 下的 Markdown。
2. `npm run build` 重新构建。
3. 本地 `python http.server` 预览核对。
4. （可选）`npm run gen` 让 AI 批量起量草稿，再人工润色。
5. 攒一批后手动 `git push` 做版本备份（本项目不接自动同步插件）。
6. 部署：传 `out/` 到服务器 + Cloudflare 前置。
