## 二、SEO 分析

### 2.1 技术 SEO（强项，92）
- **抓取与索引**：`robots.txt` 对 `GPTBot / ChatGPT-User / CCBot / anthropic-ai / PerplexityBot / Google-Extended / Bytespider` 全部 `Allow: /`，仅屏蔽 `/api/ /admin/ /_next/`，对 AI 爬虫友好。
- **sitemap**：`sitemap.xml` 共 **66** 条 URL，`lastmod` 实时、优先级梯度合理（首页 1.0 → 分类 0.8 → 产品 0.7 → 文章 0.6）。
- **canonical**：首页 `<link rel="canonical" href="https://www.aoobee.com/">` 正确，无重复 URL 风险。
- **速度**：首页 TTFB ≈ **0.16s**，文章页 ≈ 0.35s（含 308 重定向一跳），纯静态托管，性能优秀。
- **安全头**（`vercel.json`）：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`X-Frame-Options: SAMEORIGIN`、`Permissions-Policy` 限制敏感 API——基础安全加固到位。
- **OG 图**：`opengraph-image.tsx` 运行时以 `image/png` 提供，分享体验正常。

### 2.2 页面内容质量（短板，55）
- 文章正文长度差异大，best/compare/review 类普遍 **326–1025 中文字**，未达「详实可引用」阈值（建议 800–1500 字）。
- FAQ 仅 **2–3 条**，对 FAQPage schema 与 AI 直接引用利用率低（建议 5–8 条）。
- 产品页内容相对最扎实（功能/定价/优缺点/场景齐全），是站内质量标杆。

### 2.3 索引与权威（最弱，30）
- **新域名、零优质外链**：Domain Authority 近乎为 0，搜索引擎与 AI 均无「信任信号」。
- **Google 快照陈旧**：此前探测显示首页摘要为旧描述（现已修正为「收录 9 个产品」，与线上 9 个产品一致，描述本身准确）。
- **`base.aoobee.com` 风险**：该子域为遗留 SEO 垃圾内容（黑帽排名广告），非本仓库可控，需你查 DNS/Cloudflare 清理，避免品牌混淆与负面关联。

### 3.2 llms.txt（AI 爬虫地图）
- 共 **67** 条，格式为 `- 分类/产品/文章: url`，覆盖 8 分类 + 9 产品 + 全部文章/点评。
- 头部注明「所有内容以 Markdown 维护于 content/，可用 Obsidian 管理」——直接告诉 AI 你的内容源结构，利于引用。

### 3.3 可引用定义块（P1-b，已生效）
- 文章页已出现「什么是 X / X 适合谁」语义化区块（如 `## 什么是人工智能？`），字段缺失时自动回退到分类真实描述，**现有 39 篇文章零改动即获该块**。
- 这是 GEO 摘录率的关键提升点：AI 回答「什么是 X」「X 适合谁」时可直接抓取。

### 3.4 GEO 待补强
- `Organization.sameAs` 为占位（`["https://www.aoobee.com","/about","/contact"]`），**未关联真实社媒**，品牌实体图谱弱。补真实社媒 URL 可显著强化「谁是 AooBee」。
- **缺 GEO 度量**：无 analytics 记录 AI 爬虫来源与引用率，无法量化 GEO 成效（见架构审查第 3 点）。

## 五、技术架构审查

### 5.1 现状
- **栈**：Next.js 16.2.9（App Router）+ React 19.2.4 + Turbopack；TypeScript 5；Tailwind 4。
- **内容模型**：Markdown-in-repo（`gray-matter`）+ 自定义 loader；当前 **65 个 .md**；构建期 SSG，生成 **149 条路由**（含 OG 图）。
- **OG 图**：`opengraph-image.tsx` 运行时生成（`export const dynamic = "force-static"`），正确适配 Vercel serverless（不用静态导出）。
- **自动生成**：`scripts/gen-llms.ts` 预构建生成 `llms.txt`；`next build` 生成 `sitemap.xml` / `robots.txt`。
- **依赖精简**：`next/react/gray-matter/zod/clsx/date-fns/lucide-react/openai`，无重型冗余（`openai` 真用于 `src/lib/llm`）。
- **配置**：`trailingSlash: true`、`images.unoptimized: true`；`vercel.json` 安全头。

### 5.2 架构优点
- **Markdown 即源**：git 版本化、AI 友好、零数据库成本、可随时迁移——对 GEO 内容站是优良范式。
- **构建期全静态**：SEO/速度最优，无运行时 DB 依赖。
- **约定固化**：`AGENTS.md` + `docs/运营手册/` 让 AI 与人都能接手，协作边界清晰。
- **结构化数据自动注入**：内容写 FAQ/评分即自动获得 schema，运营零额外成本。

### 5.3 风险与改进点
| 项 | 现状 | 建议 |
|---|---|---|
| GEO 度量盲区 | 无 analytics，不知 AI 是否引用 | 加隐私友好统计 + AI 爬虫日志（P1-5） |
| 整站重建 | 无 ISR，每次内容改动全量重建+部署（~1–2 分钟） | 当前可接受；若日更频繁，评估 On-Demand ISR |
| `out/` 残留 | 本地有 558 文件旧静态导出目录 | 已被 `.gitignore` 忽略、零跟踪，**无害**；本地可删 |
| `sameAs` 占位 | Organization 未连真实社媒 | 补 URL（P1-4） |
| 内容校验 | 无 CI 校验 | 扩量到 300+ 时加（P2-7） |
| `base.aoobee.com` | 仓库外 DNS 风险 | 用户侧清理（P0-3） |

### 5.4 架构结论
架构健康、可维护、面向 GEO 设计良好，**不存在结构性技术债**。后续唯一需主动引入的是「度量闭环」（analytics + 引用监控），否则 GEO 投入无法量化 ROI。
