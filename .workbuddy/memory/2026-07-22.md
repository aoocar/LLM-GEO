## 项目浏览 + 部署架构讨论
- 完整浏览 AooBee 项目：Next.js16(App Router) + React19 + Prisma7 + Postgres16 + Tailwind4 的全行业产品/服务目录站，面向 GEO/SEO 优化。

- 结论要点：
  - 该应用是动态全栈（SSR + 写库），Vercel 无远程库不可行（serverless 无法用本地文件库，且本地 PC 的 Postgres 无法被 Vercel 公网访问）。

  - 轻量云 VPS 上 docker-compose(Next.js+Postgres) 最推荐：公网可达、无需托管 DB 服务。

## 内容管理架构转向：Markdown 文件源（22:04）
- 用户核心诉求澄清：admin 后台只有 AI 生成、无手动增删改界面；反复用 AI 录入/管理很繁琐。希望内容以 Markdown 文件形式存在，用 Obsidian 类软件管理，无需掌握 SQL 即可运营。
- 这是"文件即内容源"(file-based CMS) 模式，对 GEO/SEO 更友好（干净 markdown 易被 AI 引用）。
- 映射：Product → content/products/<分类>/<slug>.md（frontmatter+正文）；Article(guide/comparison/best/faq) → content/articles/<type>/<slug>.md；Review 可砍或转 markdown。
- 关键决策待用户拍板：
  1) Obsidian→服务器同步方式：Git 流(Obsidian Git插件commit/push→服务器webhook git pull，推荐，复用现有GitHub) vs 直同步流(Syncthing/rsync 到服务器卷 + Next运行时读盘)。
  2) 内容转 Markdown 后是否弃用 Postgres：目录站建议弃用，方案B简化为"纯Next.js读markdown + Cloudflare"，连 Docker/DB 都不需要，更契合低配服务器+无SQL运营。
- 影响：/api/save 从"写DB"改为"写.md文件"，AI与人工创作统一为markdown流水线；需把 db.xxx.findMany() 查询替换为 markdown loader；/search 仍需补(可用FlexSearch扫markdown)。这是架构重构非小修补。
- 当前：仅讨论方案，未落地。待用户确认同步方式与是否弃用Postgres后再出设计。

## 项目本质定位澄清（22:16）—— 关键决策依据
- 用户明确：本项目本质是"给搜索引擎和AI爬虫喂信息源"的 GEO/SEO 站，**不是给人提供交互服务的网站**。评论/用户交互等动态功能明确不需要在本项目实现，后期交互可借助第三方现成工具对接（如评论组件/表单服务）。
- 推论：无用户数据需存储 → **Postgres 完全没必要**（彻底支持上一轮的"弃用DB"判断）。
- 内容更新"比较频繁" → 发布管线必须低成本：倾向"运行时读 markdown + ISR + git pull 即生效"，避免每次改动全量 rebuild。
- 优先级翻转：正常站优化 UX，本站立项优化"可抓取性 + 内容新鲜度 + 结构清晰度"。可额外暴露每页原始 markdown 或 llms-full.txt 作为机器首选接口。
- 这把方案B进一步简化为"纯 Next.js 读 markdown + Cloudflare 边缘"，连 Docker/DB 都可省；用户交互类功能走第三方嵌入，不污染核心。

## 构建/托管方式最终决策（23:00+）
- 用户推翻"岔路A(推源,云端Vercel/CF Pages自动构建)"推荐，理由成立：
  1) 频繁推送(一天几十上百次)会烧额度：CF Pages 仅 500次/月、Vercel 100次/天，且 Next 静态导出每次全量rebuild，白白耗构建分钟；
  2) 规模上万~几十万篇时云端构建必然超时(CF Pages 单次20分钟上限制)，云端跑不完。
- 确定走"岔路B：本地高配电脑 next build → 推静态产物(out/) → 静态托管"，云端零构建额度消耗、本地可无限次build当检查点。
- 托管落点：倾向方案2(自有服务器 nginx 伺服 out/ + Cloudflare 前置缓存/DDoS/HTTPS)，但**先本地跑通再执行2**；GitHub 仅当 md+代码的版本备份库(手动批量push)，不再作构建触发器。
- 工作流定稿：本地 AI 脚本生成 md → Obsidian 管理 → 本地 next build 校验(改好再推) → 攒批量手动 git push(不用Obsidian自动推插件)。
